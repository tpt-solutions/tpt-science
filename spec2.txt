# tpt-science Specification

## 1. Purpose
Simulation and modeling substrate for the TPT Solutions science verticals: differential equations, structured-grid PDE, multi-scale simulation orchestration, probabilistic programming, rigid-body physics, quantum simulation, tomographic imaging, astrodynamics, and advanced scientific computing methods.

## 2. Scope & Boundaries
- IN SCOPE: First-principles scientific computing, ODE/DAE solvers, molecular dynamics, DFT, CFD core, and domain-specific scientific models.
- OUT OF SCOPE: Engineering code checks, CAD geometry, or system-level optimization.
- DEPENDS ON: `tpt-math` (numeric, linalg, signal-fft, prob, optimize).

| Crate | Domain | no_std | Description |
|---|---|---|---|

## 4. Design Principles
- **std-only posture**: All crates in this pillar are `std`-only by design due to heavy linear algebra and simulation requirements.
- **Modularity**: Each crate represents a distinct scientific domain or numerical method.
- **Interoperability**: Crates must expose standard traits for state exchange (e.g., passing MD coordinates to DFT solvers).

## 5. Build Order
1. Core Simulation & Math (ode, grid, sim-core, rigid, astro, reaction-network).
2. PPL, Image, Quantum.
3. Advanced Scientific Methods (md, dft, cfd-core, kinetics).
4. Domain-specific science (hemodynamics, electrophys, climate, ocean).

## 6. Downstream Consumption
- `tpt-materials` uses `md`, `dft`.
- `tpt-medical` uses `hemodynamics`, `electrophys`.
- `tpt-earth` uses `climate`, `ocean`, `cfd-core`.
- `tpt-process` uses `kinetics`, `cfd-core`.
- `tpt-physics` uses `cfd-core` as a backend for meshless/multiphysics extensions.
